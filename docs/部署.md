# 部署文档

## Windows 本地一键环境（推荐）

仓库已提供 Docker Compose 和 PowerShell 脚本。MySQL、Redis、MinIO、Maven、npm 和 pnpm 的可写数据都会放在项目根目录的 `.runtime` 下（本仓库位于 D 盘时即全部落在 D 盘）。

```powershell
# 首次执行：安装依赖并拉取基础设施镜像
.\scripts\setup-dev.ps1

# 日常启动
.\scripts\start-dev.ps1

# 日常停止（不会删除数据库或 MinIO 数据）
.\scripts\stop-dev.ps1
```

启动后用户端为 `http://localhost:8090`，管理端为 `http://localhost:8089`，后端为 `http://localhost:8080`，MinIO 控制台为 `http://localhost:9001`。容器 MySQL 映射到主机 `13306`，避免与本机已有 MySQL 的 `3306` 冲突。

> 初始化 SQL 只包含媒体 URL 和元数据，不包含原始音频/封面文件。若要播放内置 499 首歌曲，仍需把原始数据上传到 MinIO 的 `vibe-music-data` 桶；在线搜索歌曲不依赖这些文件。AI 助手需要在启动前设置 `DASHSCOPE_API_KEY`，其他功能不需要。

> 可以参考视频教程：[部署视频](https://www.bilibili.com/video/BV1rDeqzkEaY/)

## 客户端端部分

```bash
cd vibe-music-client
```

推荐使用pnpm进行依赖安装
确保pnpm可用
1. 依赖安装
```bash
pnpm install
```
2. 配置环境变量

- 复制 .env.development 文件并重命名为 .env.development.local (推荐) 或直接修改 .env.development。
- 修改文件中的 VITE_APP_BASE_API 为你本地运行或部署的 Vibe Music Server 后端服务地址。
```bash
# .env.development.local

# Vibe Music Server API 地址 (示例)
# 请确保替换为你的实际后端服务地址和端口
VITE_APP_BASE_API = 'http://localhost:8080'
```

3. 启动
```bash
pnpm dev
```

4. 打包
```bash
pnpm build
```



## 管理端部分

```bash
cd vibe-music-admin
```
同客户端部分，使用pnpm进行依赖安装然后启动。

## 服务端部分

1. 各种配置
按照`application-dev.example.yml`中的内容创建一份`application-dev.yml`文件,填写相应的配置。
2. 数据库MySQL
确保数据库可用，并创建数据库`vibe_music`(或者按需更改)。
```sql
CREATE DATABASE vibe_music CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
然后向数据库中导入`vibe-music.sql`文件(位于项目根目录/sql目录下)。
3. 确保Redis可用
4. MinIO

> MinIO 2025年5月起的开源版的网页管理控制台移除了大量管理功能，可以考虑使用旧版。
如果一定要使用阉割版，可以参考视频教程：[部署视频](https://www.bilibili.com/video/BV1rDeqzkEaY/)

这里给出视频中用到的命令：
```bash
mc alias set myminio http://127.0.0.1:9000 minioadmin minioadmin

mc alias list

mc anonymous set download myminio/vibe-music-data

mc anonymous get myminio/vibe-music-data
```
原始音乐数据下载：参考原作者的仓库：[vibe-music-server](https://github.com/Alex-LiSun/vibe-music-server)
