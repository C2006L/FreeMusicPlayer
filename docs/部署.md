# FreeMusicPlayer 部署指南

## Windows 本地开发

需要 Windows 10/11、Docker Desktop、JDK 17+、Node.js 18+ 和 PowerShell。项目位于 D 盘时，依赖缓存及服务数据都会保存在项目的 `.runtime` 目录。

```powershell
.\scripts\setup-dev.ps1
.\scripts\start-dev.ps1
```

停止且保留数据：

```powershell
.\scripts\stop-dev.ps1
```

| 服务 | 地址 |
| --- | --- |
| 用户端 | http://localhost:8090 |
| 管理端 | http://localhost:8089 |
| Spring Boot API | http://localhost:18080 |
| Provider | http://localhost:3001 |
| go-music-api Swagger | http://localhost:3002/swagger/index.html |

默认启动 MySQL、Redis 和 go-music-api。MinIO 不是在线播放依赖，只在测试头像、附件或用户上传媒体时启用：

```powershell
.\scripts\start-dev.ps1 -WithMinio
```

管理端默认只监听 `127.0.0.1`；需要让局域网设备访问管理端时使用 `.\scripts\start-dev.ps1 -ExposeAdmin`。

### 手机 / 平板联调

手机或平板在同一局域网访问 `http://<本机局域网IP>:8090` 时，`localhost` 不再有效。先 `ipconfig` 确认 WLAN IPv4，再在启动前设置并**重启前后端**：

```powershell
$env:FMP_PUBLIC_HOST = '<本机局域网IP>'
.\scripts\start-dev.ps1
```

- 脚本会据此设置 `VITE_APP_BASE_API`、`VIBE_MUSIC_PROVIDER_PUBLIC_URL` 和 `FMP_ALLOWED_ORIGINS`；也可以分别显式设置，已有值不会被覆盖。
- 页面与 API 端口不同，`FMP_ALLOWED_ORIGINS` 必须含 `http://<局域网IP>:8090`，否则浏览器按 CORS 拦截。
- Windows 防火墙需放行入站 8090 与 18080。
- 局域网 IP 由 DHCP 分配，换网段或重启路由器后可能变化，联调前重新确认。
- 没有配置平台 Cookie 时，网易云 / QQ 多数只能返回试听片段；用户端默认搜索源已排除这两个平台，需要时仍可手动指定来源。

## 服务结构

```text
Vue :8090
  -> Spring Boot :18080
       -> MySQL :13306
       -> Redis :6379
       -> Provider :3001
            -> go-music-api :3002（主引擎）
            -> Meting（回退）
       -> MinIO :9000（可选附件）
```

`go-music-api` 作为独立 AGPL-3.0 容器运行，本仓库通过 REST 调用它，不包含其源码。

## 平台 Cookie

需要使用本人账号已有权限时，编辑被 Git 忽略的 `.runtime/go-music-api/cookies.json`：

```json
{
  "netease": "MUSIC_U=...; __csrf=...;",
  "qq": "qm_keyst=...; uin=...;",
  "kugou": "token=...; userid=...;",
  "bilibili": "SESSDATA=...;"
}
```

保存后重启。Cookie 只能赋予账号原本拥有的权限，不能解锁未购买内容。不要提交、截图或共享该文件。

## 数据库升级

新数据库执行基础 SQL 和初始化迁移；已有数据库由 `SchemaMigrationRunner` 在后端启动时检查、补齐在线曲库字段和索引，版本记录到 `fmp_schema_history`。变更前运行 `.\scripts\backup-db.ps1`，备份位于 `.runtime/backups`。迁移失败时后端启动失败，不会静默运行不兼容结构。

## 修改后端后的重建

```powershell
.\scripts\restart-backend.ps1
```

## AI 助手

默认连接本机 Ollama `http://127.0.0.1:11434`，使用已安装的 `qwen2.5:3b`。可设置 `OLLAMA_BASE_URL`、`OLLAMA_MODEL`。不会自动下载模型。

改用云端：

```powershell
$env:FMP_AI_PROVIDER = "dashscope"
$env:DASHSCOPE_API_KEY = "你的 API Key"
.\scripts\start-dev.ps1
```

`FMP_AI_PROVIDER=none` 关闭 AI。`/agent/status` 与用户端 `/status` 显示模型配置、模型缺失或服务不可达状态。单次回复最长120秒；支持停止生成，聊天内容仅保留在本次页面状态，服务端记忆按会话隔离并限制大小。

## 邮箱测试与真实 SMTP

运行 `.\scripts\start-dev.ps1 -WithMail`，在 `http://localhost:8025` 查看本地验证码邮件；Mailpit 只接收本机测试邮件，不投递到互联网。该脚本会同时设置 `FMP_MAIL_ALLOW_LOCAL=true`，否则验证码接口会拒绝往本机接收器投递。

**让外部邮箱真实收到验证码**（以 163 邮箱为例）：

1. 登录邮箱网页版，进入设置 → POP3/SMTP/IMAP，开启 SMTP 服务并生成**授权码**（授权码不是登录密码）。
2. 在启动后端的同一个终端里设置下面环境变量，然后重启后端。QQ 邮箱用 `smtp.qq.com:465`，企业邮箱按服务商文档填主机与端口；587 端口改成 `SMTP_SSL=false`、`SMTP_STARTTLS=true`。

```powershell
$env:SMTP_HOST = "smtp.163.com"
$env:SMTP_PORT = "465"
$env:SMTP_USERNAME = "你的邮箱@163.com"
$env:SMTP_PASSWORD = "上一步生成的授权码"
$env:SMTP_AUTH = "true"
$env:SMTP_SSL = "true"
.\scripts\start-dev.ps1
```

3. 后端启动日志会打印 `邮件服务目标 smtp.163.com:465（外部投递）`，表示已指向真实 SMTP。
4. 注册页点击“发送验证码”，接口返回 `邮件发送成功`，去收件箱（含垃圾箱）查收；也可用 `POST /user/sendVerificationCode` 直接验证。

未配置真实 SMTP 时，接口不再"假装成功"，而是直接返回明确原因：

```
验证码未发出：当前邮件服务指向本机接收器 localhost:1025，外部邮箱收不到。
请为后端配置真实 SMTP（SMTP_HOST、SMTP_PORT、SMTP_USERNAME、SMTP_PASSWORD、SMTP_AUTH=true）后重启；
仅本地调试可设置 FMP_MAIL_ALLOW_LOCAL=true 并在 Mailpit 中查看验证码
```

SMTP 连接或认证失败时返回 `邮件发送失败：无法通过 SMTP host:port 投递…`，同时后端日志记录完整异常。没有配置发信服务时注册和找回密码不可用，已有用户仍可登录。

## 常见问题

### 只能播放约 30 秒

这是上游提供的试听媒体。播放器会尝试严格匹配的其他来源；全部受限时显示试听提示。自己的有效 Cookie 可能获得账号本来具备的整曲权限，但项目不会绕过 VIP 校验。

### 搜索结果较少

检查 `http://localhost:3002/swagger/index.html` 和 `http://localhost:3001/health`。增强服务不可用时会回退到 Meting，来源会减少。

### 网络连接失败

```powershell
docker compose -f compose.dev.yml ps
Get-Content .runtime\logs\backend.err.log -Tail 100
Get-Content .runtime\logs\provider.err.log -Tail 100
```

### 后端地址与端口冲突

当前 API 默认18080，前端8090，管理端8089。启动脚本检查 `/health` 中的 `application=FreeMusicPlayer` 和 `apiVersion=2`。其他项目占用8080不会影响本项目；不要停止不属于本项目的进程。

如修改 `FMP_BACKEND_PORT`，同时更新前端的 `VITE_APP_BASE_API` 并重启前端；启动脚本会为它启动的前端自动设置该地址。IDE 启动需加载正确数据库配置及 JWT 密钥。

### Docker Volumes 显示 0 Bytes

本项目使用 `.runtime` 绑定挂载，不依赖 Docker 命名卷。0 Bytes 匿名卷不代表 MySQL 或 Redis 数据丢失。

## 登录安全配置

后端启动前必须设置 `VIBE_MUSIC_JWT_SECRET`，值应为至少 32 个字符的随机字符串。项目的
`scripts/setup-dev.ps1` 和 `scripts/start-dev.ps1` 会在 `.runtime/jwt-secret.txt` 自动生成并复用
本机开发密钥；通过 IDE 单独启动后端时，请在运行配置中设置同名环境变量。
